# Obsidian Integration

## Vault Location

`./brain/` (relative to the project root)

## Vault Structure

```
brain/
├── Features/      ← ticket system: one note per feature, tracks status
├── Metrics/       ← session + feature reports (auto-generated by /save)
├── Architecture/  ← system design, services, data flow
├── Codebase/      ← conventions, patterns, key modules, gotchas
├── Database/      ← schema, relationships, migration notes
├── Install/       ← local setup, env vars, dependencies
├── Decisions/     ← ADRs — why things are the way they are
├── APIs/          ← external integrations, auth, rate limits
├── Infra/         ← Docker, Terraform, CI/CD, environment configs
└── Runbook/       ← deploy, rollback, debug procedures
```

Each folder has an `index.md` — read it first before reading individual notes in that folder.

## Rules

- **Always read before editing** — never overwrite, only append/update
- **Frontmatter required** on every note: `status`, `updated`, `tags`
- **Wikilinks** `[[note-name]]` for internal links — never markdown links
- **Filenames** in kebab-case
- **NEVER write secrets** — only reference names (e.g., "see .env")
- **NEVER git push** — commit only, user pushes

## When to Update

| Trigger | Action |
|---------|--------|
| Starting a new feature | Create ticket in `Features/` (see `spec-driven-development` skill, Step 1a) |
| Feature shipped | Set `status: shipped` in `Features/<feature>.md`, add implementation notes |
| Architecture decision made | Add to `Architecture/`, or an ADR in `Decisions/` if it's a non-obvious tradeoff |
| Touching schema or running migrations | Update `Database/` |
| Adding/changing an external integration | Update `APIs/` |
| Changing setup steps | Update `Install/` |
| Refactoring a module's structure | Update `Codebase/` |
| Changing infra, Docker, CI/CD config | Update `Infra/` |
| Bug with root cause found | Add to the feature note under "Gotchas", or to `Codebase/` if it's a general pitfall |
| `/save` command | Update affected notes + generate session metrics in `Metrics/` + commit |

## How to Edit

Use the `obsidian-cli` or `obsidian-markdown` global skills for correct syntax.

Or edit directly with the Edit tool — preserve existing content, only add/modify what changed. Update the relevant `index.md` with a wikilink whenever you create a new note.

## Commit After Updating

```bash
cd brain
git add -A
git commit -m "brain: <what changed>"
# NO push
```
